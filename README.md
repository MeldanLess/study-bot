# Учебный бот: задачи, дедлайны и заметки

[![CI](https://github.com/MeldanLess/study-bot/actions/workflows/ci.yml/badge.svg)](https://github.com/MeldanLess/study-bot/actions/workflows/ci.yml)
[![Python 3.12](https://img.shields.io/badge/python-3.12-3776ab.svg)](https://www.python.org/downloads/)
[![Лицензия: MIT](https://img.shields.io/badge/лицензия-MIT-0f7b4f.svg)](LICENSE)

Telegram-бот, который помнит учебные задачи, напоминает о дедлайнах и
сжимает длинные заметки до трёх пунктов.

## Задача

Учебные задачи живут в голове и в заметках, а дедлайны — в календаре, и к
середине семестра половина из них забыта. Обычный список дел не помогает: он
требует заглядывать в него каждый день, а к концу дня это и не хочется.

Бот решает ровно три вещи, и каждая закрывает конкретную боль:

- **не дать забыть** — задача с дедлайном сама напомнит о себе, без
  напоминалок в телефоне;
- **не переписывать сроки руками** — «завтра», «через 2 часа», «20.11
  18:00» читаются как человек их пишет, а не как заполняет форма;
- **не перечитывать полстраницы** — заметка к задаче сжимается до трёх
  пунктов: что сделать, что сделано, что непонятно.

## Что он умеет

| Команда | Что делает |
|---|---|
| `/add Прочитать главу до завтра` | Добавляет задачу со сроком |
| `/add Разобрать задачу до 20.11 18:00` | Тот же срок, записанный точным временем |
| `/list` | Что осталось: номер, текст, срок |
| `/done 3` | Отмечает задачу выполненной |
| `/note 3 прочитать первые две главы` | Прикрепляет заметку к задаче |
| `/summarize 3` | Сжимает заметку до трёх пунктов через Anthropic API |
| `/help` | Справка |

Срок понимается словами: `сегодня`, `завтра`, `послезавтра`, `через 2 часа`,
`через 90 минут`, `20.11`, `20.11 18:00`, `2026-12-01 08:00`. Непонятный срок
бот называет вслух и просит переписать — молчаливый дедлайн не туда хуже.

## Стек

Python 3.12 · aiogram 3 · SQLAlchemy 2 (async) · SQLite (aiosqlite) ·
pydantic-settings · Anthropic SDK · pytest · pytest-asyncio · Ruff ·
GitHub Actions · Docker Compose · systemd

## Быстрый старт

```bash
# 1. Зависимости
pip install -r requirements.txt -r requirements-dev.txt

# 2. Настройки: токен от @BotFather и, по желанию, ключ Anthropic API
cp .env.example .env

# 3. Запуск
python -m studybot
```

После `pip install -e .` бот запускается и как команда `study-bot`.

Без ключа Anthropic API бот работает целиком — просто `/summarize` отвечает,
что суммарирование выключено. Молчаливый отказ хуже явного.

## Как это устроено

```
Telegram → bot.py → service.py → repository.py → SQLite
              ↓          ↓
           aiogram    dates.py, texts.py
                         ↓
                    ai.py → Anthropic API
```

| Слой | Файл | Что делает |
|---|---|---|
| Telegram | `studybot/bot.py` | Маршруты команд, polling, цикл напоминаний |
| Правила | `studybot/service.py` | Что бот делает с задачей: правила без Telegram |
| Сроки | `studybot/dates.py` | Разбор «завтра», «через 2 часа», «20.11 18:00» |
| Тексты | `studybot/texts.py` | Все ответы бота в одном месте |
| Хранилище | `studybot/repository.py` | Единственное место, где живёт SQL |
| Модель | `studybot/models.py` | Задача и тип для дат |
| AI | `studybot/ai.py` | Суммаризация через Anthropic API |
| Копии | `studybot/backup.py` | Резервная копия базы через backup API SQLite |

Логика (`service.py`, `dates.py`) не знает про aiogram: её можно проверить
обычными тестами — без сети, без Telegram и без фейкового клиента. Ручки
Telegram тонкие: разобрали команду, позвали сервис, отправили текст.

## Ключевые решения и компромиссы

- **Бизнес-логика отдельно от фреймворка.** Правила живут в `service.py` и
  не импортируют aiogram. Если завтра фронтенд сменится на HTTP-API, правила
  останутся как есть, а тесты — тоже.
- **Один цикл напоминаний вместо таймера на задачу.** Таймер на каждую задачу
  жил бы в памяти процесса и пропал бы после перезапуска вместе с
  напоминанием. Здесь бот раз в минуту смотрит в базу: база переживает
  перезапуск, и напоминание не теряется. Поле «напомнили» не даёт прислать
  одно и то же дважды.
- **Время хранится в UTC, а показывается в местном.** SQLite не хранит часовой
  пояс, и значение, сохранённое с `tzinfo`, возвращается наивным — сравнение
  падает с `TypeError` в самый неподходящий момент, в проверке «пора ли
  напомнить». Поэтому даты ходят через свой тип: на записи всё приводится к
  UTC, на чтении возвращается осознанный UTC, а наивное время не принимается
  вовсе.
- **Год без даты — ближайший будущий.** «20.11» в декабре означает 20 ноября
  следующего года, а не прошлое 20 ноября: человек, который пишет дедлайн,
  думает о будущем.
- **SQLite, потому что это бот для одного человека.** Сервер и Postgres
  здесь — лишняя работа: база помещается в файл, который копируется одной
  командой, а весь бот — один процесс.
- **Суммаризация выключена без ключа, а не «работает как-нибудь».** Бот прямо
  говорит, что ключа нет. Фича, которая молча делает вид, что работает, хуже
  отсутствующей фичи.
- **Никакой авторизации.** Бот работает с задачами того, кто ему пишет, и
  больше ни с чьими. Для одного человека это правильный объём: чужих данных у
  бота просто нет.

## Тесты

```bash
pytest --cov=studybot --cov-report=term-missing
ruff check . && ruff format --check .
```

Тесты не ходят в сеть: ни Telegram, ни Anthropic API. Суммаризатор подменяется
заглушкой, база — временным файлом SQLite.

## Развёртывание

Бот сам ходит в Telegram по long polling, поэтому публичного адреса у него нет:
нужны только сервис, который поднимается после перезагрузки, и резервные
копии базы.

```bash
docker compose up -d
```

Пошаговая инструкция — в [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md): systemd-юнит,
таймер резервного копирования и откат на предыдущую версию.

## Что в проекте честно

- **Напоминания приходят, пока бот запущен.** Если сервер лежит, пропущенные
  сроки не придут позже «сами» — бот пришлёт их при следующем запуске, но
  одним списком, а не по одному. Это осознанный размен: точность «в минуту
  после дедлайна» стоит работающего процесса, а он не работает вечно.
- **Суммаризация — это пересказ, а не вывод.** Модель может упустить деталь,
  и проверить её нельзя. Поэтому заметка остаётся у человека, а `/summarize`
  — это способ быстро перечитать, а не замена чтению.
- **Модель в настройках, а не в коде.** Список моделей меняется, поэтому
  `ANTHROPIC_MODEL` задаётся в `.env`, и бот подставляет значение как есть.
- **Бот не помнит, кто что писал, кроме Telegram-идентификатора.** Имя не
  хранится: задача принадлежит пользователю по его `user_id`, и чужие задачи
  не находятся — их просто нет в выборке.

## Что дальше

- Разделить «что сделать», «что сделано» и «что непонятно» прямо в боте — по
  одной заметке на задачу этого не вытащить.
- Напоминания по расписанию занятий, а не только по дедлайну.
- Экспорт задач в ICS, чтобы они попадали в календарь.
